# 私人聚会 · 小程序

几个朋友聚会时玩小游戏用的微信小程序：创建/加入房间、房间内最多 12 个座位、实时语音、游戏规则介绍。

默认走 `mock/`（本地 `wx.storage` 模拟），**不启动任何服务就能在开发者工具里跑通登录 → 建房 → 谁是卧底的整条链路**。后端 `AsrielPartyBackend`（Django）也已经写好了，改两个配置值就能切过去（见下文「接上自己的后端」）。

> **狼人杀和你画我猜没有 mock 实现**，必须切到后端才能玩 —— 免得两套规则慢慢跑偏。

---

## 快速开始

1. 用微信开发者工具「导入项目」，目录选 `AsrielParty`，AppID 用你自己的。
2. 直接编译运行即可。默认 `config/index.js` 里 `env = 'mock'`，不需要后端。

首次进入首页 → 点「用微信头像和昵称登录」→ 微信弹出原生头像选择器（默认就是你的微信头像）→ 紧接着确认昵称（键盘上方有「使用微信昵称」，点一下就好）→ 完成登录。

创建房间时 mock 会自动塞 **3 个模拟玩家**进去（小林、阿哲、丸子）。他们不只是占座位——开局后会**过几秒自己投票**，所以你一个人在开发者工具里也能把发牌 → 投票 → 结算 → 下一轮的整条链路走完。真实后端接上后这些人不会出现。不想要的话，把 `mock/handlers.js` 里的 `MOCK_AUTO_BOTS` 改成 `0`。

想清空本地假数据：开发者工具控制台执行 `wx.clearStorageSync()`。

## 已实现的功能

| 需求 | 实现位置 |
|---|---|
| 微信登录 | `pages/index` — 首页一步登录：`open-type="chooseAvatar"` 选微信头像 → `<input type="nickname">` 确认昵称 → `wx.login` 换 openid |
| 编辑个人资料 | `pages/profile` — 随时改头像和昵称 |
| 创建房间 | `pages/create` — 选游戏类型、房间名；**狼人杀要选版型**（决定座位数与角色配置），其他游戏固定 10 个座位 |
| 加入房间 | `pages/join` — 输入 6 位房间号，或从「我参与的房间」直接进 |
| 游戏规则介绍 | `pages/rules` + `pages/rule-detail` — 5 个游戏的完整规则、角色说明、小贴士 |
| **谁是卧底（已可玩）** | `pages/room` + `components/undercover-panel` — 房主设卧底人数（默认 1，上限小于人数一半）→ 随机抽词发牌 → 大家自由描述 → 小程序内投票 → 自动结算并判定胜负。词库在 `data/words.js` |
| **狼人杀牌桌（准备阶段）** | `pages/room` — 座位**左右两列**，中间留空（只铺一层背景）；底部是**开麦/闭麦 + 准备/开始** |
| **狼人杀（已可玩，要后端）** | `components/werewolf-panel` — 开局后换成能操作的牌桌：**左右两列座位夹着中间的「进程记录」，底部是当前要做的操作**。开局先弹一次身份卡（之后点自己头像随时能看）→ 夜晚按角色依次行动（封锁 / 摄梦 / 刀人 / 守护 / 查验 / 验尸 / 用药）→ 天亮宣布 → 发言 → 投票（可弃票，**投票中谁都看不到别人投没投**）→ 平票 PK → 结算（**票型按「投给 3 号的：1、2、5」这样分组公布**）→ 猎人开枪。**规则判定全在后端** `party/werewolf.py`；每个版型的规则细节（含「7 人最后幸存者」的补充说明）在规则页能读到 |
| **点头像打标签** | 点其他人的头像 → 从「好人 / 狼人 + 版型里的身份（预言家 / 守卫 / 平民…）」里选一个标记他。准备阶段和**牌桌里都能用**（牌桌上长按头像也直接打标签）。标记只存在你自己手机上 |
| **你画我猜（已可玩，要后端）** | `components/draw-panel` — 开局后就是一块画板：画手在本地实时画、每一笔增量同步给别人（约 1 秒延迟），其他人打字猜；猜对得分、画手也跟着得分，一局下来每人轮流当一次画手 |
| **人机（一个人也能玩）** | 房间 →「⋯ → 加人机」，房主可以补几个人机进来。它们由**后端**自动驱动：轮到自己画会涂几笔、轮到夜晚会选目标、白天会投票。这样 6 人狼人杀、4 人卧底，一个人一台手机也能跑起来 |
| 版型 | 狼人杀有两个：**6 人新手场**（1 预言家 / 1 守卫 / 2 平民 / 2 狼人）和 **7 人最后幸存者**（觉醒摄梦人 / 女巫 / 猎人 / 守墓人 / 平民 + 隐狼 / 狼妃，屠边）。7 人场的夜晚顺序是「狼妃封锁 → 狼人夜袭 → 女巫 → 守墓人 → 觉醒摄梦人」。加版型要两边各加一份（`utils/games.js` 的 `variants` + 后端 `party/constants.py`），**夜晚唤醒顺序由 `night.order` 自动排出来**，不用手写 |
| 创建时选游戏类型 | `pages/create` 的游戏卡片 |
| **创建后可切换游戏类型** | `pages/room` — 房主点顶部游戏标签，或「更多 → 切换游戏类型」 |
| 房间内布局 | 狼人杀用专属牌桌；其他游戏用环形座位（最多 12 个） |
| **人不满也能开局** | 只要当前人数达到该游戏的最低人数（`games.js` 里的 `minPlayers`），房主就能开始 |
| 实时语音 | `utils/voice.js` — 封装 `wx.joinVoIPChat`，含说话光圈。**免费方案单房间上限 10 人**，详见下文 |

房间内还能：准备/取消准备、房主开始/结束本局、房主踢人、复制房间号、分享邀请、被踢或房间解散时自动退出。

## 登录与用户标识

登录流程：首页登录按钮（`open-type="chooseAvatar"`）→ 微信原生头像选择器 → 昵称确认弹层 → `wx.login` 拿 code → 后端换 `openid` → 完成。之后在 `pages/profile` 随时改头像和昵称。

**有三样东西拿不到，后端设计时别按它们来：**

| 想要的 | 实际情况 |
|---|---|
| 一键获取真实微信昵称头像 | ❌ `wx.getUserProfile` 自 2022-10-25 起只返回「微信用户」+ 灰色默认头像；官方唯一合规方式是「头像昵称填写能力」，必须由用户点选/填写 |
| 微信号（`wxid_...` 或自定义微信号） | ❌ 微信从未开放给小程序，属敏感字段，官方明确禁止接口返回 |
| 手机号 | ❌ 个人主体不可用：`getPhoneNumber` 只对**非个人主体且已认证**的小程序开放，且自 2023-08-28 起按次收费（0.03 元/次） |

**所以用户唯一标识用 `openid`**（用户在本小程序内的永久唯一标识）。后端 `users` 表拿它做唯一键，另外预留一列 `unionid`——以后去微信开放平台绑定同主体账号后，就能跨 App / 公众号 / H5 识别同一个用户了。`nickname` / `avatar` 是可随时修改的普通字段，不要拿来做标识。完整说明见 `docs/backend-api.md`。

> 正式发布前要在小程序后台配置**用户隐私保护指引**，勾选**头像昵称**（头像昵称填写能力）和**麦克风**（实时语音），否则正式环境这两个能力会被拦住。开发阶段不影响。

## 改动之后跑一下自检

```
python scripts/check-structure.py
```

依次检查：页面是否都在 `app.json` 注册、`usingComponents` 路径能否解析、wxml 用到的自定义组件是否注册、每个 `bind*` 事件在对应 js 里是否有实现、JSON 是否合法、JS 括号是否配平，以及下面这条 WXML 反模式。

**WXML 的坑：`wx:else` / `wx:elif` 不能和 `wx:for` 写在同一标签上。** 同一标签有 `wx:for` 时，该节点会先被当成循环节点，`wx:else` 就找不到前面的 `wx:if` 兄弟，编译直接报 `Bad attr 'wx:else'` with message `wx:if not found`。列表的空态判断必须用 `<block wx:else>` 把带 `wx:for` 的节点包起来：

    <view wx:if="{{loading}}" class="empty">加载中…</view>
    <view wx:elif="{{!list.length}}" class="empty">还没有内容</view>
    <block wx:else>
      <view wx:for="{{list}}" wx:key="id">…</view>
    </block>

## 接上自己的后端

后端是 Django（`AsrielPartyBackend`，**已经写好了**）。小程序这边只需要两步：

1. 打开 `config/index.js`，把 `env` 改成 `'dev'`，并把 `baseUrl` / `wsBaseUrl` 改成你的服务器地址。
2. 把后端跑起来 —— 步骤见 `AsrielPartyBackend/README.md`（接口协议见 `docs/backend-api.md`）。

改完之后不用动任何页面代码 —— `utils/api.js` 会自动从 mock 切到 `wx.request`。

正式环境注意：
- `baseUrl` 必须是 https，`wsBaseUrl` 必须是 wss，且域名要在小程序后台的「服务器域名」白名单里。
- 本地调试要在开发者工具里勾「不校验合法域名」（`project.private.config.json` 里的 `urlCheck` 已经设成 `false`，正常不用手动点）。
- 手机真机预览时 `baseUrl` 要填电脑的**局域网 IP**（不能是 `127.0.0.1`），后端也要用 `runserver 0.0.0.0:8000` 启动。

## 几个需要知道的限制

**实时语音上限 10 人。** `wx.joinVoIPChat` 是微信唯一免费、官方内置的多人实时语音能力，但它硬性限制**单房间最多 10 人**。房间座位可以开到 12，超过 10 人时房间页会给降级提示，建议那时改用微信群语音通话，小程序照样能主持游戏。

另外语音还有两个前置条件：
- 需要在**小程序管理后台 → 开发 → 接口设置**里开通实时语音接口权限；
- 签名必须由后端用 appsecret 计算（`docs/backend-api.md` 里有算法说明），小程序里算不了。

**没开通权限时**语音按钮会给出可读的中文提示，不影响其他功能。

**头像在 mock 模式下是本地临时路径。** 重启小程序后可能失效，座位组件会自动回退成昵称首字。接上后端走了 `/api/user/avatar` 上传就正常了。

**渲染引擎是默认的 WebView**，不是 Skyline。官方模板默认开了 Skyline，但 `project.private.config.json` 里 `skylineRenderEnable` 是 `false`（两处配置矛盾），常规 UI 在 WebView 下 CSS 行为更确定，所以统一走 WebView。想换回 Skyline 就在 `app.json` 里加 `"renderer": "skyline"` 并实测各页面样式。

**房间同步目前是 3 秒轮询** `GET /api/rooms/detail`（`config/index.js` 的 `roomPollInterval`）。后端上 WebSocket（Django Channels）后可以调大或关掉，`pages/room/room.js` 里已经有 `render(room)` 可以直接复用推送数据。

**你画我猜的画板是另一套更快的轮询**（`GET /api/rooms/draw/poll`，约 0.7 秒）—— 画一笔要等 3 秒才出现在别人屏幕上就没法玩了。画手那边是「本地实时画 + 攒 0.6 秒批量提交」，所以自己画着是跟手的，别人看着大约滞后 1 秒。
